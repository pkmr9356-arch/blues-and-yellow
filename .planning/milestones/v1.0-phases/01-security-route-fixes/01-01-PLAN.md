# Plan 01-01: Admin Route Authentication & Role-Based Access Control

## Objective
Enforce robust server-side authentication and role-based authorization on all administrative routes (`/admin` and `/admin/leads`) using Supabase Auth (`auth.getUser()`), verified custom claims (`app_metadata.role = 'admin'`), and Next.js middleware, completely shielding customer lead PII from unauthorized public visitors and non-admin authenticated users, preventing open-redirect vulnerabilities, and preserving existing brand aesthetics and database integrations.

## Technical Analysis & Authorization Design

### Authentication vs. Authorization Gap
- `supabase.auth.getUser()` verifies a user's cryptographic session and identity, but does **not** establish that the user is an administrator.
- Inspection of the repository and Supabase project revealed zero existing auth code, zero users currently in `auth.users`, and no custom role tables.
- **Vulnerability**: If authentication alone were checked, any user who obtains an account in the Supabase Auth project would be granted access to customer lead PII.

### Smallest Safe Admin Authorization Rule
To enforce strict authorization without adding new tables, dependencies, or paid services:
1. **Rule Definition**: A user is authorized as an administrator **if and only if** they meet both strict conditions:
   - **Condition 1 (Tamper-Proof Custom Claim)**: `user.app_metadata?.role === 'admin'`. In Supabase Auth, `user_metadata` can be edited by the user, but `app_metadata` can **only** be modified by the service-role or Supabase dashboard administrator; users cannot elevate their own privileges.
   - **Condition 2 (Mandatory Strict Allowlist - Fail-Closed)**: The user's email must be explicitly listed in the mandatory `ADMIN_EMAILS` environment variable (e.g. `ADMIN_EMAILS=hello@bluesandyellow.agency,admin@bluesandyellow.agency`). If `ADMIN_EMAILS` is unset, empty, or whitespace, access strictly fails closed (`false`). **Zero domain-wide wildcard fallbacks** (e.g. `@bluesandyellow.agency`) are permitted.
2. **Helper Implementation in `src/lib/supabase-server.ts`**:
   ```typescript
   export function isAuthorizedAdmin(user: { email?: string; app_metadata?: { role?: string } } | null): boolean {
     if (!user || !user.email) return false;

     // 1. Must possess verified admin role in app_metadata (tamper-proof from client)
     if (user.app_metadata?.role !== 'admin') return false;

     // 2. Mandatory, strict allowlist from environment variable (fail-closed if missing or empty)
     const rawAllowlist = process.env.ADMIN_EMAILS;
     if (!rawAllowlist || rawAllowlist.trim() === '') {
       console.error('Security Warning: ADMIN_EMAILS environment variable is not configured. Failing closed.');
       return false;
     }

     const allowedEmails = rawAllowlist
       .split(',')
       .map((e) => e.trim().toLowerCase())
       .filter((e) => e.length > 0);

     const userEmail = user.email.trim().toLowerCase();
     return allowedEmails.includes(userEmail);
   }
   ```
3. **Execution Boundary**:
   - Both `src/middleware.ts` and `src/app/admin/leads/page.tsx` verify `isAuthorizedAdmin(user)`.
   - If `!isAuthorizedAdmin(user)`, access is immediately blocked with a redirect to `/admin/login?error=unauthorized`.
   - **Zero service-role queries are executed, and zero lead records are fetched** unless `isAuthorizedAdmin(user)` returns `true`.

## Tasks

### Task 1: Supabase SSR Helper & Middleware Admin Guard
- **Files**: `src/lib/supabase-server.ts`, `src/middleware.ts`
- **Action**:
  1. In `src/lib/supabase-server.ts`:
     - Add SSR helper `createSupabaseServerClient()` using `@supabase/ssr` `createServerClient` reading/writing cookies via Next.js `cookies()`. Maintain existing `createClient()` export.
     - Export `isAuthorizedAdmin()` helper implementing the strict authorization rule (tamper-proof `app_metadata.role = 'admin'` + mandatory strict `ADMIN_EMAILS` allowlist verification; zero wildcard domain fallback).
  2. Create `src/middleware.ts` with config matcher `['/admin', '/admin/:path*']`.
  3. In `src/middleware.ts`:
     - Instantiate an SSR Supabase client reading request cookies and writing response cookies.
     - Call `const { data: { user }, error } = await supabase.auth.getUser();`.
     - If `pathname === '/admin/login'`:
       - If `user` is valid and `isAuthorizedAdmin(user)`, redirect to `/admin`.
       - Otherwise, allow request to proceed to the login screen.
     - For all other `/admin` routes (`/admin`, `/admin/leads`, etc.):
       - If `error || !user`, redirect to `/admin/login?next=${encodeURIComponent(pathname)}`.
       - If `user` is authenticated but `!isAuthorizedAdmin(user)`, redirect to `/admin/login?error=unauthorized`.
       - If `user` is valid and authorized, allow request to proceed with updated session cookies.
- **Verification**:
  - `curl -I http://localhost:3000/admin/leads` (no cookies) -> Returns `HTTP 307 Temporary Redirect` to `/admin/login?next=%2Fadmin%2Fleads`.
  - `curl -I -H "Cookie: sb-access-token=fake-token" http://localhost:3000/admin/leads` -> Returns `HTTP 307 Temporary Redirect` to `/admin/login` (forged cookie rejected by `getUser()`).
  - Authenticated session with non-admin user -> Redirected to `/admin/login?error=unauthorized`.
  - Public routes (`/`, `/services`, `/work`, `/contact`, `/start-a-project`) return `200 OK` untouched by `src/middleware.ts`.
- **Regression Check**:
  - Verify public landing page and subpages load without redirects or performance degradation.

  3. Display localized error feedback if redirected with `?error=unauthorized` ("Access denied: Administrator privileges required").
  4. Form submission calls Supabase Auth `signInWithPassword({ email, password })`.
  5. Implement safe redirect validation function:
     ```typescript
     function getSafeRedirectPath(nextParam: string | null): string {
       if (!nextParam) return '/admin';
       // Must start with a single slash followed by 'admin', reject protocol-relative (//) or backslashes
       if (/^\/admin(\/|$)/.test(nextParam) && !nextParam.startsWith('//') && !nextParam.includes('\\')) {
         return nextParam;
       }
       return '/admin';
     }
     ```
  6. Upon successful login, redirect user to `getSafeRedirectPath(searchParams.get('next'))`.
- **Verification**:
  - Submit invalid credentials -> Inline error appears; no redirect occurs.
  - Test open redirect attack: Log in with `?next=https://malicious.com` or `?next=//evil.com` -> Safely redirects to `/admin`, completely ignoring the external domain.
- **Regression Check**:
  - Form layout adheres to Tailwind design tokens and responsive containers.
