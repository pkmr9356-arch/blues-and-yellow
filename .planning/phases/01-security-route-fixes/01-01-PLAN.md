# Plan 01-01: Admin Route Authentication & Access Control

## Objective
Enforce server-side access control on all administrative routes (`/admin` and `/admin/leads`) using Supabase Auth and Next.js middleware, completely shielding prospective customer lead PII from unauthorized public visitors while maintaining brand design aesthetics.

## Proposed Files to Create / Modify
1. `src/middleware.ts` (New): Intercepts all `/admin/:path*` requests except `/admin/login`. Validates Supabase auth cookies via `@supabase/ssr`. Redirects unauthenticated requests to `/admin/login`.
2. `src/lib/supabase-server.ts` (Modify): Enhance Supabase server helper with an SSR cookie-aware client (`createSupabaseServerClient` using `@supabase/ssr` / Next.js `cookies()`), while preserving the existing fallback `createClient()` export for legacy background actions.
3. `src/app/admin/login/page.tsx` (New): Clean, branded administrative login screen utilizing Navy/Blue/Yellow color tokens and Erode typography, providing email/password credential submission with client-side status feedback.
4. `src/app/admin/page.tsx` (Modify): Server component adding defense-in-depth session verification and a sign-out control.
5. `src/app/admin/leads/page.tsx` (Modify): Server component defense-in-depth verification before querying the Supabase `leads` table.

## Tasks

### Task 1: Supabase SSR Helper & Middleware Access Guard
- **Files**: `src/lib/supabase-server.ts`, `src/middleware.ts`
- **Action**:
  1. In `src/lib/supabase-server.ts`, export a server component client helper utilizing `@supabase/ssr` with Next.js cookie handling (`createServerClient`), preserving the existing `createClient()` signature for existing actions.
  2. Create `src/middleware.ts` configured with `matcher: ['/admin', '/admin/:path*']`.
  3. In middleware, inspect request cookies for active Supabase Auth session tokens.
  4. If user is unauthenticated and pathname is not `/admin/login`, redirect with HTTP 307 to `/admin/login?next=${encodeURIComponent(pathname)}`.
  5. If user is authenticated and visits `/admin/login`, redirect to `/admin`.
- **Verification**:
  - Request `/admin/leads` in a clean browser session without cookies; verify it returns an immediate HTTP 307 redirect to `/admin/login`.
  - Verify public routes (`/`, `/services`, `/work`, `/contact`, `/start-a-project`) pass through middleware untouched with zero latency penalty.
- **Regression Check**:
  - Ensure public pages load and render normally without authentication challenges.

### Task 2: Admin Login Page
- **Files**: `src/app/admin/login/page.tsx`
- **Action**:
  1. Build an administrative sign-in page at `/admin/login`.
  2. Implement email and password input fields with clear labels and autofocus.
  3. Handle sign-in submission via client-side Supabase auth (`createBrowserClient` or server action sign-in).
  4. Display error message if invalid credentials are submitted (e.g., "Invalid login credentials").
  5. Upon successful authentication, refresh session cookies and redirect to destination specified in `?next=` query parameter (defaulting to `/admin`).
  6. Apply existing agency brand styling (`bg-white`, `text-[var(--navy)]`, `bg-[var(--blue)]` buttons, Inter/Erode typography).
- **Verification**:
  - Visit `/admin/login` directly; verify form renders with email, password, and submit button.
  - Submit invalid credentials; verify an inline error message is displayed and no redirect occurs.
- **Regression Check**:
  - Verify typography and color variables match `src/app/globals.css` and `tailwind.config.js`.

### Task 3: Defense-in-Depth Protection on Admin Pages
- **Files**: `src/app/admin/page.tsx`, `src/app/admin/leads/page.tsx`
- **Action**:
  1. In `src/app/admin/page.tsx`, add a server-side session check using `createSupabaseServerClient()`. If no user session is returned, invoke `redirect('/admin/login')`.
  2. In `src/app/admin/leads/page.tsx`, enforce the same server-side session guard prior to executing `.from('leads').select('*')`.
  3. Add a "Sign Out" button/form in the admin navigation to clear auth cookies via `supabase.auth.signOut()`.
  4. Preserve the existing lead table presentation (`name`, `email`, `status`, `created_at`).
- **Verification**:
  - Attempt direct curl / fetch to `/admin/leads` with headers stripped; verify zero lead data is present in HTML response payload.
  - Log in with valid admin credentials; verify lead records load accurately from Supabase.
- **Regression Check**:
  - Verify layout shell and table styling on `/admin/leads` remain intact.

## Threat Model & Acceptance Criteria
- **Threat (T-01-01)**: Unauthenticated visitor navigates to `/admin/leads` to scrape prospective client emails and project scopes.
  - *Mitigation*: Both Next.js middleware and server component route handlers block execution and redirect to `/admin/login`.
- **Acceptance Criteria**:
  - `curl -I http://localhost:3000/admin/leads` -> HTTP 307 Redirect to `/admin/login`.
  - Zero rows from `leads` table are serialized or returned to unauthenticated clients.
  - Valid admin login sets secure cookies and displays lead table.
